# Paper Tanks Constitution

## Core Principles

### I. Spec Before Code
Каждая фича MUST начинаться с speckit-спецификации и плана до кода.
Агент MUST NOT писать продуктовую реализацию, пока нет утверждённых spec и plan.
Рationale: игра маленькая, цена «сразу в код» — разъезд правил тумана войны и UI.

### II. Hidden Information
Полный флот, ёлки и ящики живут только на компьютере стола.
Вид игрока MUST NOT содержать координаты чужого флота.
Устройство игрока MUST NOT решать мимо/ранен/убит.
Рationale: иначе партия — подглядывание, а не морской бой.

### III. Local Table, No Cloud
Стол MUST быть локальным процессом на компьютере в той же сети, что и игроки.
Нет учёток, интернет-лобби и публичного матчмейкинга.
Прямая связь двух телефонов без компьютера — вне конституции этой версии.
Рationale: двое за одним столом; облако не нужно и ломает «без интернета».

### IV. Rules Are Testable
Правила расстановки, выстрела, декораций и вида игрока MUST быть проверяемы без экрана.
Утечка чужого флота в виде игрока MUST ловиться тестом.
Рationale: туман войны нельзя доказать «на глаз».

### V. Paper Over Arcade
Поле MUST читаться как тетрадь в клетку; танки и декорации — как синяя ручка.
Линовка «в линейку» на игровом поле запрещена.
Рationale: настроение бумаги важнее эффектов шутера.

## Constraints

- UI этой версии — русский.
- Два игрока, одна комната, без зрителей и ИИ.
- Компьютер в LAN обязателен: отдаёт страницу, QR и судит клетки.
- Feature spec описывает продукт, не git-процесс и не стек.

## Development Workflow

**Владелец** читает артефакты, утверждает развилки и merge.
**Агент** пишет spec/plan/tasks/код и ведёт git, но не перепрыгивает gate и не мержит сам.

Spec, plan и tasks задают *что* строить. Шаги 7–14 задают *как* это попадает в `dev`.
Этот процесс MUST NOT дублироваться в feature spec.

| Шаг | Кто | Действие |
|-----|-----|----------|
| 1 | Агент | `/speckit-specify` — зафиксировать или обновить spec |
| 2 | Владелец (gate) | Прочитать spec. Если всё ясно — к шагу 3. Если есть неясности — `/speckit-clarify`, **не** `/speckit-plan` |
| 3 | Агент | `/speckit-plan` — технический план по утверждённому spec |
| 4 | Владелец (gate) | Прочитать plan. Отклонить — вернуться к plan/clarify. Утвердить — к шагу 5 |
| 5 | Агент | `/speckit-tasks` — упорядоченный список работ |
| 6 | Агент | `/speckit-analyze` — необязательно, но полезно после tasks (сверка spec ↔ plan ↔ tasks) |
| 7 | Агент | Git: актуальный `dev` → ветка `feat/<topic>` или `fix/<topic>`. Не затирать чужие локальные изменения — спросить. Нет `dev` — спросить базовую ветку |
| 8 | Агент | `/speckit-implement` **уже на этой ветке**, только запрошенный скоуп |
| 9 | Агент | Тесты, линт, сборка. Коммит на английском, [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) |
| 10 | Агент | Push и pull request **в `dev`** |
| 11 | Агент | `/review-bugbot` при checkout’нутой ветке этого PR. База сравнения — `dev` |
| 12 | Владелец | Решает, какие находки чинить. Агент **не** правит находки в том же шаге, пока владелец явно не попросил |
| 13 | Агент | Babysit: зелёный CI, конфликты, замечания ревью. Продуктовые споры — владельцу, не угадывать |
| 14 | Владелец, затем агент | Только после явного «мержить»: merge → удалить remote-ветку **после** успешного merge → `git checkout dev && git pull` |

Один промпт не должен смешивать specify, implement и bugbot: у слоёв разные стоп-краны.

**Ограничения:** не force-push без явной просьбы; не мержить при красном CI, недостающих обязательных ревью или открытых блокирующих комментариях; не удалять remote-ветку до подтверждённого merge; `/review-bugbot` не запускать вместо шага 2 или 4 (это ревью кода, не spec/plan).

## Governance

Эта constitution имеет приоритет над привычками агента и над текстом в feature spec, если они расходятся.
Поправки MUST менять версию (MAJOR — ломка принципа, MINOR — новый принцип или workflow, PATCH — формулировки) и дату Last Amended.
Pull request в `dev` MUST быть согласован с принципами I–V и с Development Workflow.
Сложность сверх spec MUST быть обоснована владельцу, не добавлена молча.
